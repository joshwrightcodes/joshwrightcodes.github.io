Work at Mitti

These projects follow a backend service from the day it is created to the way it is observed in production.

Create in Backstage

Project leadBackstage, MCP Actions

Creating a service through a custom CLI tool and a static pipeline took more than 24 hours, with multiple reviews and manual steps. I led the work to replace them with the Backstage scaffolder.

  • A new service now reaches production, fully operational, in under 15 minutes.
  • A template and automated controls replaced the review of each service. The Platform team approves every template change through a pull request. Only a bot account can commit, its commits are signed, and each change must pass the existing PR checks.
  • I rolled out the Backstage MCP Actions backend, so that engineers can reach scaffolder operations and catalog data from MCP clients.

Build on Kubernetes

Project leadBuildkite, agent-stack-k8s, Go

I led the move of Buildkite from long-lived EC2 agents to agent-stack-k8s, in a central and isolated build account. About 400 polyglot backend services now share one standard build and deploy workflow.

Adoption came from removing work. We migrated services on behalf of their teams, and any team could still build its own plugin. An extensible plugin gave teams a golden path that took build and deploy concerns away from them.

  • Permissions: each pipeline and step holds only the permissions it needs.
  • GitHub: all operations use scoped GitHub App credentials, and bots sign their commits.
  • Secrets: a custom plugin retrieves AWS secrets, passes them to build steps and redacts them from output.
  • Standards: a Go plugin approach with a reference design replaced disparate bash scripts.
  • Coverage: plugins generate pipelines, and handle caching, web deploys, secrets, i18n and GitHub operations.

Ship on ARM64

Project leadko, .NET container support, distroless

I led the retooling of all backend services for multi-arch builds. 95% of them now run on ARM64, which delivers ongoing cost savings.

  • Services moved to distroless images wherever supported, built with ko and .NET container support, which reduces their attack surface.
  • Services now integrate ASAP, Atlassian's service-to-service authentication protocol, directly.
  • Base images no longer carry the AWS CLI.

Open source

bk-agent-stack-orchard

Author and maintainerGo, Tart, Orchard, OpenTelemetry

A Buildkite stack controller that runs each macOS job in its own clean Tart VM through Orchard, and deletes the VM when the job ends. It applies the agent-stack-k8s model to macOS. It is an early release, currently v0.1.1.

  • Each VM gets a short-lived token for its own job only.
  • The controller checks free VM slots before it reserves a job.
  • Metrics, traces and logs export through OpenTelemetry (OTLP).
  • A nightly load test runs 50 synthetic workers and 500 jobs.
  • Releases are signed, and the design is recorded in public architecture decisions.
